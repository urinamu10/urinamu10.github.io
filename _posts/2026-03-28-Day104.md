## 1. [Weather Observation Station 5](https://www.hackerrank.com/challenges/weather-observation-station-5/problem?isFullScreen=true)

- 테이블

![alt text](https://s3.amazonaws.com/hr-challenge-images/9336/1449345840-5f0a551030-Station.jpg)



- 문제 
```plaintext
1. STATION 테이블의 가장 긴 이름과 짧은 이름을 가진 `CITY` 이름을 쿼리하시오.
2. 가장 짧고 긴 도시 이름의 길이를 각각 쿼리하시오. (ex: 도시, 길이)
```

- 풀이

1. 각 테이블에서 `char_length` 문법을 사용하고 `order by`절에서 
해당 도시와 컬럼의 길이를 가진 도시 한곳을 쿼리합니다.

2. 각 컬럼 두개를 `Union`으로 수직결합합니다.

```sql
(SELECT city, char_length(city)
from station
order by char_length(city) asc,
city asc
limit 1)

union all 

(SELECT city, char_length(city)
from station 
order by char_length(city) desc,
city asc
limit 1)
;
```

## 2.[Weather Observation Station 6](https://www.hackerrank.com/challenges/weather-observation-station-6/problem?isFullScreen=true)

- 테이블

![alt text](https://s3.amazonaws.com/hr-challenge-images/9336/1449345840-5f0a551030-Station.jpg)
- 문제

```plaintext
1. STATION 테이블의 CITY 컬럼에서 모음(i,e,a,o,u)으로 시작하는 테이블을 쿼리하시오. 
```

#### `Like` 조건절로 풀이

where 조건절에서 like 문을 OR 조건식으로 분할하여 쿼리합니다.

```sql
SELECT distinct city
from station
where city like "i%" 
    or city like "e%" 
    or city like "a%"  
    or city like "o%" 
    or city like "u%" ;
```

#### 정규식 표현 (Basic Syntax)

두번째 방식은 정규표현식을 사용한 방법입니다

저번에 한번 사용했던 기억이 있지만 기억이 나지 않아 다시 한번 암기해보려고합니다.

>정규 표현식의 핵심 기호들 
{: .prompt-tip }

- `^` (Caret): 문자열의 시작을 의미합니다.
- `&` (Dollar): 문자열의 끝을 의미합니다.
- `[]` (Brackets): 괄호안에 나열된 문자 중 하나라도 일치하는 것을 찾습니다. (ex: [aeiou])
- `.` (Dot): 임의의 한 문자를 의미합니다.
- `ㅣ` (Pipe): OR(또는) 연산자로 사용됩니다.
- `*` (Asterisk): 앞의 문자가 0회 이상 반복됨을 의미합니다.

기존에 사용했던 LIKE 문법은 조건이 늘어날수록 가독성이 저하되게되지만, 정규표현식(REGEXP)은 동일한 논리를 매우 간결하게 표현할 수 있었습니다.

> 하지만 정규표현식이 지나치게 복잡해질 경우나 대량의 데이터셋에서 복잡한 정규표현식을 사용하게 될 경우, 단순 LIKE 연산이나 인덱스 기반의 검색보다 연산 비용이 높을 수 있습니다.

- 조건문에 REGEXP를 선언해준 후 시작기호`^`다음 `[]`속에 저희가 필터링할 문자들을 집어넣습니다.

```sql
SELECT distinct city
from station
where city REGEXP '^[ieauo]' ;
```

## 3. 이번주 오브젝트 (3.23 ~ 3.27)

#### 3-1 MAC OS 환경설정 및 최적화 

벌써 데이터분석 부트캠프가 종료되고 2주가량이 지났습니다.

그동안 데이터 엔지니어로의 큰 전환을 결심하였고, UNIX기반의 Macbook pro를 주문하였습니다.

또한, mac OS의 터미널 `zsh`와 친해지기 위해 다양한 명령어들을 공부하였고, homebrew를 통한 애플리케이션 핸들링도 해보았습니다.

또한 docker를 처음으로 배웠으며 docker를 통한 postgresSQL을 컨테이너를 띄워 가벼운 테이블을 엔지니어링도 해보았습니다.

기존 docker 프레임워크를 좀 더 가볍게 구동해주는 orbstack으로 교체하였고, 필요한 환경 세팅을 전부 완료할 수 있었습니다.

제 목표는 9월 내 주니어 DE로써의 취업이라는 명확한 목표가 있습니다.

가장 큰 약점인 학위와 경력공백에 대한 부분들을 자격증과 포트폴리오로써 기업에게 입증해야합니다.

#### 3-2 필요한 앱과 도구들

AI와 다양한 엔지니어링 아티클의 도움을 받아 필수적인 도구들을 설치하였습니다.

1. 개발 및 인프라 제어 환경 (Casks)

    - **orbstack**: 가상 머신(VM) 기반의 무거운 Docker Desktop을 대체하는 경량화 컨테이너 엔진으로 메모리와 CPU 점유율을 동적으로 할당하여, 향후 데이터 베이스 및 Airflow 파이프라인의 구동 시 발생할 리소스 병목을 원천적으로 차단하는 도구라고합니다.

    - **Cursor & Visual Studio Code**: 기존 데이터 분석에서도 사용했던 VSCode입니다. 특히 Cursor를 추가로 활용하여 코드를 입력하고 해석하거나 디버깅을 할 때 학습시간을 줄이는것이 부족한 시간을 채워 줄 수 있다고 판단하였고, vscode는 기존 레노버의 설정과 동일하게 세팅하였습니다.

    - **iterm2**: Mac 기본 터미널을 대체하는 에뮬레이터로 화면 분할, 정밀한 탐색, 텍스트 하이라이팅 등등 CLI(Command Line Interface) 제어의 시각적 가시성을 극대화합니다.
    특히 최근엔 AI로 보조하는 터미널 도구들도 나오고 있지만 아직 학습단계에선 iterm2로도 충분할것이라고 생각합니다.

2. 생산성 및 워크플로우 최적화 (Casks)

    - **Arc**: 작업 스페이스 분리와 동기화에 특화된 크로미움(Chromium) 기반 브라우저로 제 모바일과 연동하여 사용할 수 있고 무엇보다 스페이스 그룹화 등 UI가 정말 너무 깔끔해서 마음에 드는 새로운 브라우저 도구입니다.

    - **Notion**: 부트캠프 이전부터 꾸준하게 사용해왔고 어쩌다보니 아키이빙 상까지 거머쥘 수 있게 만들어주 노션은 파편화된 에러로그 기록부터 다양한 관계형 DB까지 앞으로의 커리큘럼 진행을 추적할 수 있는 제가 가장 사랑하는 생산성 도구입니다.

    - **Karabiner-Elements**: 윈도우 레노버를 부트캠프에서 대여받아 사용하다가 다시 Mac으로 돌아오니 마치 왼손잡이가 오른손으로 글을 쓰는 느낌을 받았습니다.
    기존 키 설정보다 훨씬 섬세한 조절을 할 수 있는 도구입니다.

    - **Rectangle**: 화면 분할 단축키 도구입니다. 터미널 에디터 웹 브라우저를 동시에 띄워두며 작업해야하기때문에 정말 중요하죠!

    - **Claude & Slack**: AI 질의응답 및 협업 생태계 구축을 위한 커뮤니케이션 도구입니다.

3. 코어 시스템 및 종속성 (Formulae)

    - **git**: 분산 버전 관리 시스템으로 소스코드의 변경 이력을 추적하고, 팀 단위 협업의 기반을 마련하며, GitHub 블로그의 정적 파일 배포를 통제합니다.

    - **rbenv & ruby-bulid**: 다중 Ruby 버전을 시스템 내에 격리하여 통제하는 환경 관리 도구로, 제가 vscode에서 작업한 내용들을 chirpy 블로그 양식으로 로컬 웹서버 (`localhost:4000`)에서 충돌 없이 구동하기 위해 필수적으로 요구되는 아키텍처입니다.
