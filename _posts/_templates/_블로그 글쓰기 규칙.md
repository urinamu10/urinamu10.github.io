# 블로그 글쓰기 규칙

## 1. 파일명과 URL
- 위치: `_posts/YYYY-MM-DD-슬러그.md`
- 슬러그: 영문 소문자 + 하이픈. 예) `de-week3-docker-compose`
- URL은 `/posts/슬러그/` 가 됩니다.
- 정렬은 파일명 날짜와 front matter의 `date`로 결정됩니다. 슬러그에 번호를 넣을 필요가 없습니다.
- 같은 날 글이 여러 개면 `date`의 시간(10:00, 11:00 ...)을 다르게 적습니다.
- 이미 발행한 글의 파일명은 바꾸지 않습니다(링크가 깨집니다).

## 2. 카테고리 (최대 2단계, 순서가 중요)

| 글의 종류 | categories |
| --- | --- |
| 주간·일간 학습 기록 | `[Data Engineering, TIL]` |
| SQL 코드카타 등 문제 풀이 | `[Data Engineering, CodeKata]` |
| 기술 개념 정리 | `[Data Engineering, Docs]` |

- 첫 번째 값이 상위, 두 번째 값이 하위입니다. 철자와 대소문자를 항상 똑같이 씁니다.
- 새 종류가 필요하면 하위 카테고리를 먼저 이 표에 추가하고 쓰세요.

## 3. 태그
- 구체적인 주제를 3~5개. 영문은 소문자(`docker`, `airflow`), 한글은 그대로(`코드카타`).
- 같은 대상은 같은 표기로 통일합니다(`Docker`와 `docker`를 섞지 않기).

## 4. description (홈 목록 미리보기)
- 한 문장, 60~80자 안팎.
- "목차", 제목 반복, 인사말은 쓰지 않습니다.
- 읽고 나서 얻는 것이나 핵심 결론을 적습니다.
  - 좋은 예: `Docker 컨테이너로 PostgreSQL을 띄우고 로컬 환경을 정리한 과정과 막힌 지점`
  - 나쁜 예: `목차 1. Docker는 뭘까?`

## 5. 제목 규칙
- TIL: `[DE-Week N-M] 주제`
- CodeKata: `[SQL CodeKata] 주제`
- Docs: `[Docs] 기술명 — 한 줄 설명`

## 6. 본문
- 목차는 직접 쓰지 않습니다(`toc: true`면 오른쪽에 자동 생성).
- 다이어그램을 쓰면 front matter에 `mermaid: true`를 켭니다.
- 이미지는 `assets/img/` 아래에 두고 영문 파일명을 씁니다.

## 7. 새 글 만드는 순서
1. `_templates/`에서 맞는 템플릿을 복사해 `_posts/`에 붙여넣고 파일명을 위 규칙대로 바꿉니다.
2. `title`, `description`, `date`, `tags`를 채웁니다.
3. 작성 후 커밋·푸시하고 Actions 배포를 확인합니다.
